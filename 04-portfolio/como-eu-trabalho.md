# Como eu trabalho

## Posicionamento

Product Owner de produtos de IA sob medida. Faço a ponte entre a dor do negócio e o que a engenharia constrói: discovery, requisitos, escopo, priorização e aceite. Minha profundidade técnica é de especificação. Não programo.

## O que faço em cada projeto

| Frente | O que entrego |
|---|---|
| Discovery | Dor quantificada, processo atual, dados disponíveis e métrica de sucesso |
| Requisitos | PRD versionado, épicos, histórias e critérios de aceite testáveis |
| Escopo | Recorte de MVP, registro de decisões, negociação de mudanças |
| Integração negócio e tecnologia | Papel de cada sistema, limites técnicos, dependências e riscos, levantados com a engenharia |
| Execução | Handoff com DoR completa, acompanhamento ativo do backlog |
| Aceite | Roteiro de testes, demonstração, aceite registrado e auditoria pós-entrega |

## Regras que não negocio

- **Critério de aceite testável ou não é critério.** Observável, binário, verificável sem interpretação.
- **Investigação não é critério de aceite.** Vai para tarefa ou DoD.
- **PRD congelado antes dos cards.** Requisito ambíguo é retrabalho com data marcada.
- **Promessa da venda vai para o papel.** O que foi demonstrado ao cliente entra no PRD, dentro ou fora do escopo.
- **Entregue não é aceito.** Aceito é quando o critério passou.

## Como converso com engenharia

- Levo o problema e as restrições, não a solução pronta.
- Pergunto pelos limites de cada sistema antes de prometer a funcionalidade: o que a API aceita, latência, volume, o que o sistema de terceiro não processa.
- Quando o sistema não suporta o desenho, mudo o desenho e registro a decisão.

## Como me comunico

- Atualização específica e rastreável: qual item, com quem foi falado e quando.
- Decisões com identificador (D-xx) e pendências com identificador (Q-xx), para que nada se perca entre reuniões.
- Item que está travando é sinalizado cedo, com dono.
